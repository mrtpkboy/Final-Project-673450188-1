# สคริปต์นำเสนอ: ส่วนทดสอบ API ด้วย Postman (ประมาณ 4–5 นาที)

## เตรียมก่อนขึ้นพรีเซนต์

- [ ] รัน `npm run db:seed` และ `npm run dev` ค้างไว้ (แอปเปิดที่ `http://localhost:3000`)
- [ ] เปิด Postman แล้ว Import `postman/Expense_API.postman_collection.json` ไว้แล้ว
- [ ] ที่แท็บ Variables ของ Collection ตรวจ `email` = `admin@example.com`, `password` = `admin1234`
- [ ] ลองกด Run collection ทดสอบก่อน 1 รอบให้เขียวทั้งหมด แล้วปิดหน้าผลลัพธ์ (ให้เหลือแต่ตัวแปร `expenseId` ที่ถูกเติมใหม่ตอนสาธิตจริง)
- [ ] ขยายโฟลเดอร์ `0. Login` และ `1. Expenses` ไว้ให้เห็นรายการ request ทั้งหมด

---

## 1) เปิดเรื่อง (ประมาณ 30 วินาที)

> "ส่วนต่อไปคือการทดสอบ REST API ของระบบครับ นอกจากหน้าเว็บแล้ว ระบบของเรามี API ให้เรียกใช้โดยตรง
> เราจึงใช้ **Postman** ซึ่งเป็นโปรแกรมสำหรับส่ง request ไปหา API แล้วดูผลลัพธ์ได้ทันที
> ผมเก็บ request ทั้งหมดไว้เป็น **Collection** เดียว ใครได้ไฟล์นี้ไป Import แล้วทดสอบซ้ำได้เหมือนกันทุกครั้ง"

*(ชี้ที่ Collection "Expense Tracker API" ที่แถบซ้าย)*

> "ใน Collection มี 2 โฟลเดอร์ครับ โฟลเดอร์ 0 คือการ Login และโฟลเดอร์ 1 คือการเพิ่ม ดู แก้ ลบ รายจ่าย"

---

## 2) โฟลเดอร์ 0: ระบบต้อง login ก่อนถึงจะใช้ API ได้ (ประมาณ 1 นาที 30 วินาที)

**0.1 ยังไม่ login → 401** *(กด Send)*

> "เริ่มจากทดสอบว่า API ปกป้องข้อมูลจริงไหม ผมยังไม่ได้ login แล้วลองขอรายการรายจ่าย
> จะเห็นว่าได้ **401 Unauthorized** ครับ แปลว่าคนที่ไม่ได้ login เข้าถึงข้อมูลไม่ได้"

*(ชี้ที่ Status 401 และแท็บ Test Results ที่ขึ้นเขียว)*

**0.2 ขอ CSRF token** *(กด Send)*

> "ระบบ login ใช้ Auth.js ซึ่งมีการป้องกัน CSRF จึงต้องขอ token ก่อน ตรงนี้ได้ token กลับมา
> และผมเขียน script ใน Postman ให้เก็บค่าไว้ในตัวแปรอัตโนมัติ ไม่ต้อง copy เอง"

**0.3 Login** *(กด Send)*

> "ขั้นต่อไปส่ง email กับ password ไปที่ endpoint login ได้ **200** ครับ
> Postman จะเก็บ session cookie ไว้ให้เอง ทำให้ request ต่อ ๆ ไปถือว่า login แล้ว"

*(อาจกดปุ่ม Cookies ใต้ปุ่ม Send ให้กรรมการเห็นว่ามี cookie ชื่อ `authjs.session-token`)*

**0.4 ตรวจ session** *(กด Send)*

> "ตรวจดูว่าตอนนี้เราเป็นใคร จะเห็นอีเมลของ admin และ role เป็น ADMIN"

---

## 3) โฟลเดอร์ 1: ทดสอบ CRUD (ประมาณ 2 นาที)

**1.1 POST สร้างรายการ** *(ชี้ Body ที่เป็น JSON แล้วกด Send)*

> "สร้างรายจ่ายใหม่ ส่งชื่อ จำนวนเงิน หมวดหมู่ และวันที่ไปเป็น JSON ได้ **201 Created**
> พร้อม id ของรายการกลับมา Postman จะจำ id นี้ไว้ใช้ในขั้นตอนถัดไปให้อัตโนมัติ"

**1.2 POST ข้อมูลผิด → 422** *(กด Send)*

> "คราวนี้ผมส่งข้อมูลผิดทุกช่อง ชื่อว่าง จำนวนเงินติดลบ หมวดหมู่และวันที่ไม่ถูกต้อง
> ระบบตอบ **422** พร้อมบอกว่าผิดช่องไหนบ้าง แสดงว่าฝั่ง server ตรวจข้อมูลเองจริง ไม่ได้พึ่งแค่หน้าเว็บ"

**1.3 GET ทั้งหมด และ 1.4 ค้นหา/กรอง** *(กด Send ทั้งสองอัน)*

> "ดึงรายการได้ 200 พร้อมข้อมูลแบ่งหน้าและยอดรวม ข้อ 1.4 ใช้ Query Params ค้นหาคำว่า 'ทดสอบ'
> ในหมวดอาหาร จะได้เฉพาะรายการที่ตรงเงื่อนไข
> และเพราะผม login เป็น ADMIN จึงเห็นรายการของทุกคน ถ้าเป็นผู้ใช้ทั่วไปจะเห็นเฉพาะของตัวเอง"

**1.5 GET by id → 1.6 PUT → 1.7 DELETE → 1.8 GET หลังลบ** *(กด Send ต่อเนื่อง)*

> "ดูรายการเดียวด้วย id ได้ 200 แก้ไขด้วย PUT ได้ 200 จะเห็นชื่อและจำนวนเงินเปลี่ยนไป
> ลบด้วย DELETE ได้ 200 แล้วลองขอรายการเดิมอีกครั้ง คราวนี้ได้ **404 Not Found**
> แปลว่าลบออกจากระบบจริง"

## 4) รันทั้งชุดในครั้งเดียว (ประมาณ 30 วินาที)

*(คลิกขวาที่ Collection → Run collection → กด Run)*

> "ทั้งหมดที่เพิ่งกดทีละอัน ผมรันรวดเดียวได้ด้วย Collection Runner ครับ
> Postman ส่งทุก request ตามลำดับและตรวจผลให้อัตโนมัติ จะเห็นเครื่องหมายถูกสีเขียวทุกข้อ
> ครอบคลุมทั้ง 401, 201, 422, 200 และ 404"

*(รอให้ Runner ทำงานจบ ชี้ที่สรุป Passed)*

---

## 5) สรุป (ประมาณ 20 วินาที)

> "สรุปคือ API ของเรามี 5 endpoint ครบ create, read, update, delete และ list ที่ค้นหา/กรองได้
> มีการตรวจสิทธิ์ด้วย 401 ตรวจข้อมูลด้วย 422 และจัดการรายการที่ไม่มีด้วย 404
> ทั้งหมดทดสอบซ้ำได้ง่ายด้วย Postman Collection ที่แนบมากับโปรเจกต์ครับ"

## คำถามที่อาจถูกถาม

| คำถาม | คำตอบสั้น ๆ |
| --- | --- |
| ทำไมไม่ใช้ curl? | curl ทำได้เหมือนกัน แต่ Postman เห็นผลเป็นภาพ เก็บเป็น Collection ส่งต่อให้คนอื่นได้ และมี test อัตโนมัติ |
| ทำไม login ต้องขอ CSRF ก่อน? | Auth.js ป้องกันการหลอกให้ผู้ใช้ส่งคำขอโดยไม่รู้ตัว จึงต้องส่ง token คู่กับ cookie |
| Postman รู้ได้ยังไงว่าเรา login แล้ว? | หลัง login server ส่ง session cookie กลับมา Postman เก็บไว้และแนบให้ทุก request ถัดไป |
| USER ธรรมดากับ ADMIN ต่างกันยังไงใน API? | USER เห็นและแก้ได้เฉพาะรายการของตัวเอง ADMIN เห็นทั้งหมด (ลองเปลี่ยน `email`/`password` ใน Variables แล้วรันใหม่ได้) |
| ถ้า request ไม่ผ่านจะรู้ได้ไง? | ดูแท็บ Test Results ใต้ผลลัพธ์ จะขึ้นสีแดงพร้อมบอกว่าข้อไหนไม่ตรงที่คาดหวัง |

## ถ้ามีปัญหาระหว่างพรีเซนต์

- ทุกอันได้ 401 หลัง login → รัน 0.2 → 0.3 → 0.4 ใหม่ตามลำดับ
- 1.5–1.8 ได้ 404 ตั้งแต่แรก → ยังไม่ได้รัน 1.1 (ยังไม่มี `expenseId`)
- ส่งไม่ออก (ECONNREFUSED) → ลืมรัน `npm run dev`
- แผนสำรอง: เปิด `http://localhost:3000/api-test` พิมพ์ URL ตรง ๆ แล้วกด "ทดสอบทั้งหมด" จะได้ผลแบบเดียวกันบนหน้าเว็บ
